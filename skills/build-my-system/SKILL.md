# סקיל המערכת שלנו

אני תלמידה בקורס פיתוח בעזרת AI, בוגרת מגמת תכנות. אני בונה מערכת אמיתית לעסק שבחרתי, לאורך עשרה מפגשים.
מדברים איתי בעברית, בלשון נקבה, ובקצרה. מותר מונחים מקצועיים. אחרי כל צעד אומרים לי במשפט או שניים מה השתנה, ואיך בודקים.

הטכנולוגיות של הקורס כבר נקבעו: React עם Vite ו־TypeScript, ‏Supabase, ‏Vercel ו־GitHub. לא מציעים אחרות.

## חלק 1: התכנון

התכנון שלי נמצא בקובץ `תכנון המערכת.md` בתיקיית הפרויקט. הוא המקור לכל מה שבונים.
- בקשה שכתובה בתכנון: בונים.
- משהו שלא כתוב בתכנון, או ש"לא עכשיו" לפיו: לא בונים ישר. אומרים לי מה כתוב בתכנון, ומציעים קודם את הסקיל plan-my-system כדי להוסיף את זה לתכנון. מחכים לתשובה שלי.
- הסקיל לא מותקן? מציעים להתקין אותו מ־https://github.com/ruthprissman/ai-dev-course.

## חלק 2: מערכת המסכים

### לפני שבונים
1. קוראים את `תכנון המערכת.md`: התפקידים (שלב 2), התהליך המרכזי (שלב 4), המידע והדוגמאות הבדויות (שלב 5), המסכים (שלב 6) וההרשאות (שלב 7).
2. מחפשים את המותג: סקיל מותג ב־`.claude/skills`, הלוגו, ודף הבית שבנינו במפגש הראשון (קובץ HTML בתיקייה).
3. בודקים איתי שלושה דברים, אחד בכל פעם. מה שכבר כתוב בתכנון או במותג, לא שואלים מחדש: אומרים לי מה כתוב, ושואלים אם זה נכון.
   - העיצוב: צבעים, גופן ומראה.
   - מי רואה כל מסך.
   - הדרך בין המסכים: מאיזה מסך לאיזה מסך עוברים בתהליך המרכזי.
4. מציעים תוכנית קצרה לאישור, ולא כותבים שום קובץ לפני האישור:
   - טבלת מסכים: מסך, כתובת (route), מי רואה, מה יש בו.
   - הקבצים שייווצרו, בקצרה.
   - סדר הצעדים. אחרי כל צעד: בנייה, וגרסה עם הערה.
   - מה לא נכנס היום: מסד נתונים, כניסה אמיתית עם גוגל ושליחת מיילים. אלה מגיעים במפגשים הבאים.

### איך בונים
- הקוד נמצא בתיקייה `app` בתוך תיקיית הפרויקט. יוצרים אותה עם `npm create vite@latest app -- --template react-ts`. לא מוחקים ולא דורסים שום קובץ שכבר קיים בתיקיית הפרויקט.
- ניווט בין המסכים עם `react-router-dom`. בלי ספריות נוספות, בלי לשאול אותי קודם.
- עברית מימין לשמאל (`lang="he"`, `dir="rtl"`), והמערכת פונה למשתמשות בלשון נקבה.
- הצבעים והגופן מהמותג, במשתני CSS במקום אחד. הלוגו מועתק ל־`app/public`.
- דף הבית מהמפגש הראשון הופך למסך הראשון, בכתובת `/`, באותו מראה ובאותו תוכן. הכפתור "כניסה למערכת" מוביל למסך הכניסה.
- מסך הכניסה הוא בינתיים רק מראה: כפתור "כניסה עם גוגל" שמוביל למסך הראשי, בלי כניסה אמיתית.
- יש בתכנון יותר מתפקיד אחד? בראש המסכים מוסיפים בורר זמני "צפייה בתור:", עם הכיתוב "זמני, עד שנבנה כניסה". כל מסך מציג רק את מה שמותר לתפקיד שנבחר, לפי ההרשאות בתכנון.
- נתוני הדמה: הדוגמאות הבדויות מהתכנון, בקובץ אחד ב־`app/src/data`, עם טיפוס TypeScript לכל דבר שהמערכת זוכרת. אלה יהיו הטבלאות במסד הנתונים.
- הוספה ועדכון עובדים בזיכרון של הדף, ומתאפסים ברענון. אומרים לי את זה.
- לכל שדה יש `label`, לכל תמונה `alt`, ולכל כפתור טקסט או `aria-label`.
- בונים בצעדים: קודם השלד, הניווט והעיצוב המשותף, ואחר כך מסך אחרי מסך.
- האישור לתוכנית הוא אישור לכל הצעדים. בונים אותם ברצף, בלי לעצור לשאול: בסוף כל צעד `npm run build`, ואם הוא עובר, שומרים גרסה עם הערה שאומרת מה נבנה. עוצרים רק כשמשהו לא עובר, או כשחסר מידע.
- את שרת הפיתוח מפעילים רק בסוף, ברקע.

### בודקים לפני שאומרים "גמרתי"
1. `npm run build` בתיקייה `app` עובר בלי שגיאות.
2. מפעילים את שרת הפיתוח (`npm run dev`), ונותנים לי את הכתובת לפתוח בדפדפן.
3. עוברים יחד על התהליך המרכזי מהתכנון, מסך אחרי מסך.
4. אומרים לי אילו מהבדיקות בשלב 9 של התכנון כבר אפשר לראות במסכים, ואילו יחכו למסד הנתונים.

## חלק 3: גרסאות ו־GitHub

- אחרי כל צעד שעובד (הבנייה עוברת), מציעים לשמור גרסה, עם הערה קצרה בעברית שאומרת מה השתנה.
- לפני השמירה הראשונה: `.gitignore` עם `node_modules`, ‏`dist`, וכל קובצי `.env`. סיסמאות ומפתחות לא נכנסים לגרסה לעולם.
- "תעלה ל־GitHub", "תדחוף": שומרים גרסה אם יש שינויים, ודוחפים לריפו שמחובר. אין ריפו מחובר? מבקשים שאפתח ריפו פרטי ריק ב־github.com ואדביק את הקישור.
- הדחיפה הראשונה פותחת חלון כניסה ל־GitHub בדפדפן. אומרים לי לאשר אותו, ולא מבקשים סיסמה בצ'אט.
- בסוף כל מפגש עבודה: שומרים גרסה ודוחפים.

## בהמשך

בכל מפגש מחברים לכאן עוד חלק, לפי מה שלמדנו: מסד הנתונים, כניסה עם גוגל, העלייה לאוויר, נגישות ועוד.

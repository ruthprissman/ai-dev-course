# שומרת על המידע

הסקיל מקים פעולה אחת של GitHub Actions, שרצה בכל לילה ועושה שלושה דברים:
1. **דופק:** כותבת שורה קטנה במסד. ככה פרויקט Supabase החינמי לא נרדם אחרי שבוע בלי שימוש.
2. **גיבוי:** `pg_dump` של כל הטבלאות, גם המבנה וגם המידע, לקובץ שנשמר 30 יום ב־GitHub.
3. **הפעולה לא נכבית:** אם לא נשמרה גרסה 50 יום, היא שומרת גרסה ריקה, כדי ש־GitHub לא יכבה אותה.

התבנית של הפעולה נמצאת ליד הקובץ הזה: `keep-my-data.yml`.

## איך מדברים איתה

- עברית ברורה וקצרה, בלשון נקבה. היא בוגרת תכנות: מותר להשתמש במונח מקצועי (`pg_dump`, Secrets, workflow), עם הסבר של כמה מילים.
- לפני שמתחילים: מסבירים בשלוש שורות מה יקרה, ומחכים לאישור.
- **סודות לא מוצגים אף פעם:** לא הטוקן ולא הסיסמה של המסד. לא בשיחה, לא בפקודה שמודפסת, ולא בשום קובץ חוץ מ־`.env`.
- בסוף כל שלב: משפט אחד, מה נעשה.

## לפני שמתחילים, בודקים

1. **ענף:** בפרויקט יש את סקיל המערכת שלנו (`build-my-system`)? עובדים לפי חלק 3 שלו: לפני כל שינוי פותחים ענף, למשל `feature/keep-my-data`.
2. התיקייה שמורה בגרסאות, ויש לה ריפו ב־GitHub.
3. `gh` מותקן (`gh --version`).
   - לא מותקן: מציעים להתקין, ומחכים לאישור: `winget install --id GitHub.cli -e --accept-source-agreements --accept-package-agreements`. אם נפתח חלון של Windows שמבקש אישור, היא מאשרת.
   - מיד אחרי ההתקנה הפקודה עוד לא מוכרת בחלון הפתוח. משתמשים בנתיב המלא: `"/c/Program Files/GitHub CLI/gh.exe"`.
4. `gh` מחובר (`gh auth status`). לא מחובר: החיבור דורש חלון אינטראקטיבי, ולכן היא מריצה אותו בעצמה. נותנים לה שורה מוכנה להעתקה לטרמינל של VS Code (`Terminal › New Terminal`): `gh auth login --web -h github.com -p https`, עם הנתיב המלא אם צריך. היא מעתיקה את הקוד שמופיע, מאשרת בדפדפן, וכותבת "סיימתי".
5. **הריפו חייב להיות פרטי** (`gh repo view --json nameWithOwner,visibility`). בריפו ציבורי כל אחד יכול להוריד את הגיבוי. אם הוא ציבורי: עוצרים, ומסבירים.
6. `.env` רשום ב־`.gitignore`. אין `.env`? יוצרים אותו, ובודקים שהוא ב־`.gitignore` לפני שכותבים בו משהו.
   - הטוקן לא חובה: אם יש `SUPABASE_ACCESS_TOKEN` ב־`.env`, משתמשים בו בשלב 2. אם אין, הולכים בשלב 2 בדרך החלופית, ולא מבקשים ממנה את הטוקן.
7. מזהה הפרויקט (ref): מהכתובת `https://<ref>.supabase.co`, מהשיחה או מהקוד. לא מוצאים? שואלים אותה את הכתובת.

## השלבים

### 1. הסיסמה של המסד
מוסיפים ל־`.env` שורה ריקה `SUPABASE_DB_PASSWORD=`, ומבקשים ממנה להדביק אחרי ה־`=` את הסיסמה ששמרה כשפתחה את הפרויקט, לשמור (Ctrl+S), ולסגור את הלשונית של `.env` לפני שהיא משתפת מסך.
- הסיסמה אבדה? ב־Supabase: Project Settings › Database › Reset database password. מייצרות סיסמה חדשה ושומרות אותה אצלה, במנהל הסיסמאות.

### 2. הכתובת של המסד (לא סוד)
שולפים עם הטוקן את פרטי ה־pooler, בפקודה שקוראת את הטוקן מ־`.env` ולא מדפיסה אותו:
`GET https://api.supabase.com/v1/projects/<ref>/config/database/pooler`
לוקחים את `db_host` ואת `db_user` (`postgres.<ref>`). **פורט 5432 (Session pooler)**, גם אם בתשובה כתוב 6543.
(בטוקן צריך הרשאת Connection Pooling לקריאה. בלעדיה התשובה היא 401 או 403.)
- אין טוקן ב־`.env`, או שזה לא עובד? מבקשים ממנה: בפרויקט ב־Supabase, Connect › Session pooler, ולהעתיק לשיחה את הכתובת. היא בלי סיסמה, ולכן מותר. ממנה לוקחים את ה־host ואת המשתמש.

### 3. הסיסמה נכנסת לסודות של GitHub
בפקודה אחת, בלי להדפיס את הערך. מורידים `\r`, כי `.env` שנשמר ב־Windows מסתיים לפעמים ב־CRLF, ואז הסיסמה שגויה:
```bash
grep '^SUPABASE_DB_PASSWORD=' .env | cut -d= -f2- | tr -d '\r\n' | gh secret set SUPABASE_DB_PASSWORD
```
בודקים רק שהסוד קיים: `gh secret list`.

### 4. קובץ הפעולה
אם `keep-my-data.yml` לא נמצא ליד הקובץ הזה, מורידים אותו מ־https://raw.githubusercontent.com/ruthprissman/ai-dev-course/main/skills/keep-my-data/keep-my-data.yml ושומרים אותו ליד SKILL.md. **לא כותבים את הפעולה מהזיכרון.**
מעתיקים את `keep-my-data.yml` ל־`.github/workflows/keep-my-data.yml` בתיקייה שלה, ומחליפים בו:
- `__POOLER_HOST__` ← `db_host`
- `__PROJECT_REF__` ← ה־ref

### 5. שומרים, ממזגים ל־main
לפני ששומרים גרסה, בודקים ש־`.env` לא נכנס אליה.
הפעולה רצה רק כשהקובץ שלה נמצא ב־GitHub, בענף הראשי. לכן:
- **עובדות בענפים** (סקיל המערכת שלנו): שומרים גרסה בענף, דוחפים, ונותנים לה קישור ל־Pull Request עם כותרת ותיאור בעברית. היא ממזגת ב־GitHub וכותבת "מיזגתי". חוזרים ל־`main`, מושכים, ומוחקים את הענף.
- אין עבודה בענפים: שומרים גרסה ב־`main` ודוחפים.

### 6. הרצה ראשונה, ובדיקה
```bash
gh workflow run keep-my-data.yml
gh run list --workflow keep-my-data.yml --limit 1     # מחכים כמה שניות עד שהריצה מופיעה
gh run watch <מספר הריצה> --exit-status
```
הצליח: אומרים לה שהגיבוי הראשון מוכן ושהפרויקט קיבל דופק. מראים לה איפה רואים: ב־GitHub, Actions › שומרת על המידע › הריצה › Artifacts. ומוסיפים שמעכשיו זה קורה לבד, כל לילה, ושאם ריצה נכשלת, GitHub שולח לה מייל.

## כשמשהו נכשל

קוראים את הסיבה (`gh run view <מספר> --log-failed`), ומסבירים לה במשפט:
- `password authentication failed`: הסיסמה לא נכונה, או שנכנס לה רווח או `\r`. חוזרים לשלבים 1 ו־3.
- `server version mismatch`: הפעולה השתמשה ב־pg_dump 16. משתמשים בנתיב המלא של 17 (`$PG17`).
- `Network is unreachable` או `ENETUNREACH`: הכתובת היא Direct connection. צריך Session pooler, פורט 5432.
- `Tenant or user not found`: המשתמש צריך להיות `postgres.<ref>`, לא `postgres`.
- `could not find any workflows named keep-my-data.yml`, או 404: הקובץ עוד לא בענף הראשי ב־GitHub. חוזרים לשלב 5.
- ההעלאה נדחית עם `refusing to allow an OAuth App to create or update workflow`: לחיבור של GitHub חסרה הרשאה לקובצי פעולות. מריצים `gh auth refresh -s workflow`, היא מאשרת בדפדפן, ומעלים שוב.
- הפרויקט כבר נרדם: מבקשים ממנה להעיר אותו פעם אחת מהלוח של Supabase, ומריצים שוב.

## לראות גיבוי, ולשחזר ממנו

- **להוריד גיבוי:** `gh run download <מספר> --dir "גיבויים"`. התיקייה `גיבויים` נכנסת ל־`.gitignore` **לפני** ההורדה.
- **לשחזר:** רק אחרי שמסבירים לה מה יימחק ומה יחזור, ומחכים לאישור מפורש. עדיף לשחזר לפרויקט חדש וריק, ולבדוק שם לפני שמחליפים.

## כללים

- הגיבוי רק בריפו פרטי.
- כל עוד יש רק מידע בדוי, הגיבוי לא מוצפן. **לפני שנכנס מידע אמיתי של לקוחות:** מוסיפים לגיבוי הצפנה, עם מפתח שנשמר גם מחוץ ל־GitHub. אומרים לה את זה כשמגיעים לשם.
- אחרי שמוסיפים כניסה למערכת, גם המשתמשות הרשומות צריכות להיכנס לגיבוי. בודקים את זה כשבונים את הכניסה.
- הפעולה כבר קיימת בתיקייה? לא בונים שוב. בודקים שהריצה האחרונה הצליחה, ומספרים לה.
